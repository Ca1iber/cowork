# codex-power v076：保留16B全局加载的V混合打包

## 1. 上版本遗留问题

v075真实bank指标100%/0，但C6慢1.385%，global访问8x16B变16x8B且4x4packing。当前68仍约95us，100MT/22ST。下一轮以75bank效果为观察，检验恢复较宽global/较简单packing能否转化为时间收益。

## 2. 问题原因分析

75未证明新增global/packing是独占成本。仅降低冲突不足以提速。本版恢复原2rowx8col/16B producer，保留4row/8B consumer；为窄4B store额外旋转rowgroup，模型假设4B32lane/8B16lane，尚不是硬件保证。

## 3. 本版本解决方案

Vslot rowgroup R=(row//4%2)*4+row//8，与col低3位/高两位XOR后*4+row%4。生产者exact自研60的global16B和2rowpacking，shared4B；consumer仍75的连续4half/8B、四chunk先预取后MMA。QK/P/output/barriers及FP32累加顺序保留，C12自研68，其余12项v28黑盒。

## 4. 具体落地策略

恢复V改写后AST等于75，nonV全部不动。32x128slot4096双射，producer/consumer完整唯一，2half4B与4half8B对齐，所有逻辑operand值/顺序一致。CPP真实uint4global/uint1sharedstore/uint2operandload，MMA32/fdiv32，8192waves/8KB shared不变。预测bank0仅诊断，需独立profile。无async/sourceinjection/manualbuiltin/contentcache。
